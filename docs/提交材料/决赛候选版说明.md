# 边缘行者决赛候选版

队伍编号 313。初赛报告、作品照片和历史演示流程见[提交材料索引](../00_提交材料索引.md)。

## 初赛后的增量

- 雷达和本地预警。校准 DIR1 接近方向，区分最近一帧的判决与当前保持的报警等级。安全线程独立读取雷达和维持蜂鸣输出，网络、界面和模型调用分开处理。
- 状态和受限交互。提供带时间与来源的诊断和快照。手机经电脑网关查看板端状态和设置，设备直连仍是实验路径。保留 `approach-warn` Skill、`approach_alert` Tool 与执行回执。
- 构建和复现。增加隔离构建、候选固件源树与产物核对、主机回归和有界串口采集。板级改动随专属仓的 overlay 与补丁交付。

## 证据范围

- 2026-11-03 的板端候选固件标识为 `ew-radar-20261103-buzz-2700`，原构建二进制 SHA-256 为 `6f627e558278e99413dc71c141b10268f2f7e7e58e656e7cbd30aac51ddd2db0`。安装记录包含写入 CRC 与分段读回。人工触发记录覆盖报警显示和解除，雷达背景记录有合法空帧。仓库候选版依据该构建的源码快照整理，补充了许可证注释和测试修正。
- 11 月新增现场片段用于展示接近场景与预警屏幕。道路误报率、漏报率、提前量、目标与声光输出的同步测量，以及独立无线长稳仍待验收。
- 本地判决与本地工具链、独立 ai_agent 注册与 IPC、实际声光是不同的验证环节。主机用例覆盖软件执行链。独立框架触发到实体输出仍需板端闭环记录。

## 复现入口

1. 按[根目录说明](../../README.md)和[应用说明](../../app/edge_walker/README.md)准备 openvela 工程与板端配置。
2. 安装 `requirements-test.txt` 中的依赖，准备 GCC 和带 Tk 的 Python，运行 `python scripts/host/run_tests.py`。
3. 按 [Demo 脚本与验收步骤](Demo脚本与验收步骤.md)分别检查本地预警、Skill 与工具。演示时标明真实雷达、人工注入或模拟来源。
